# 示例一：代码功能任务

**原始输入**：帮我加个导出功能

> 类型：编码 / 功能新增。需求极模糊——"导出"没有格式、没有范围、没有技术约束。

---

**Agent（阶段 0 预检）**：判定「深度澄清」——连导出什么都没说。

**Agent（阶段 1，问 2 个）**：
> 「先澄清两点：
> ① 这个导出是给谁用的、导出成什么格式？（Excel / CSV / PDF？）
> ② 导出范围是当前页面的数据，还是支持勾选/全部？」

**用户**：给运营用的，导 Excel，支持勾选多行导出。

**Agent（阶段 2，问 2 个）**：
> 「收到。再确认两点：
> ① 技术栈是 React + Ant Design 对吧？现有列表页用的是哪个组件？（假设是，不对请纠正）
> ② 验收要不要包含「空数据/超大数据量」的边界处理？」

**用户**：对，React+AntD。边界要处理，超 1 万行要提示分批。

**Agent（阶段 3 · 任务规约）**：

```text
# Agent 任务规约【经澄清确认】
## 业务目标：让运营能自助导出筛选后的订单数据，减少研发导出需求
## 受众与用途：运营人员日常使用
## 验收成功标准：勾选多行 → 点导出 → 下载 .xlsx；空数据给提示；>1万行提示分批
## 不在本次任务范围：不做 PDF 导出、不做导出模板自定义
## 可用输入上下文：现有 AntD Table 列表页，数据源为 orders API
## 输出要求：格式=React 组件 + 导出逻辑；约束=tsx、复用现有样式；参考=现有页面交互
## 工具权限：允许调用工具=true（读现有代码）
```

**用户**：确认，开始。

> 若用 OpenCode，此规约即编码前置护栏；若用 Dify，此规约作为 `task_spec` 变量传给下游执行节点。
